MoviePlanner Agent

사용자가 말한 시간 조건을 듣고, 실제 박스오피스·러닝타임·영화관 정보를 API로 확인한 뒤, 그 시간 안에 볼 수 있는 영화와 늦어도 몇 시에 시작해야 하는지를 알려 주는 Agent입니다. 조건에 맞는 영화가 없으면 스스로 계획을 바꿔 다시 찾습니다.

Python 3.11LangGraph 1.2.10langchain-openai 1.4.3 (SSAFY GMS)Pydantic 2FastAPISQLiteHTML/CSS/JS
Agent 실행 따라가기부품별로 뜯어보기시간 판단 계산LLM과 코드의 역할Tool 4종전체 구조진행 상황

처음이라면 이 순서로: ① Agent 실행 따라가기에서 R1을 재생해 전체 흐름을 본다 → ② 부품별로 뜯어보기의 탭 1~6을 차례로 조작한다 → ③ 시간 판단 계산 슬라이더로 계산식을 확인한다 → ④ 전체 구조에서 /api/chat부터 파일을 따라간다.

대표 요청

"내일 강남에서 2시 이후에 영화 보고 7시 전에 끝내고 싶어"

1. LLM이 이해의도는 계획 수립, 조건은 내일·14:00·19:00·강남
2. Tool로 확인KOBIS 순위·러닝타임, 카카오 영화관
3. 코드가 계산러닝타임+광고 20분이 시간 안에 들어가는가

LLM만으로는 답할 수 없습니다. 지금 상영작과 러닝타임을 모르기 때문입니다. M0에서 GMS에 "어제 박스오피스 1위"를 물었을 때 조회할 수 없다고 거절했고, 실제 1위 '폭설(88분)'은 KOBIS로만 확인됐습니다.

부품별로 뜯어보기

위 시뮬레이터가 전체 흐름이라면, 여기서는 부품을 하나씩 직접 조작해 봅니다. 탭은 만든 순서이고, 각 탭은 이 부품이 하는 일 → 직접 조작 → 터미널에서 확인 순서로 읽으면 됩니다. M3 judge는 아래 시간 판단 계산에서 다룹니다. 값은 코드 규칙을 그대로 옮긴 계산이고, 영화 목록과 소요 시간은 예시입니다.

이 부품이 하는 일

외부 API 4종은 오류를 알리는 방식이 제각각입니다. KOBIS는 키가 틀려도 HTTP 200에 faultInfo를 담아 보내고, 카카오와 TMDB는 401을 보냅니다. Tool은 이 차이를 안에서 흡수하고, Agent에게는 늘 같은 모양만 돌려줍니다. 예외는 밖으로 던지지 않습니다.

Tool과 상황을 바꿔 보면서 ①과 ③이 어떻게 다른지 비교해 보세요.

    설계 원칙
    
    LLM과 코드의 역할
    
    
    LLM은 말을 이해하고 문장을 만드는 데 강하지만 계산을 틀리거나 값을 지어낼 수 있습니다. 규칙으로 정할 수 있는 일은 모두 코드가 맡습니다. 그래야 정확하고 테스트하기 쉽습니다. M10 검증에서 프롬프트로 부탁한 규칙을 LLM이 가끔 어기는 것을 확인하고, 규칙으로 정할 수 있는 몇 가지를 더 코드로 옮겼습니다(아래 M10 표시).
    
  
    
  
    
    
    LLM 맡는 일
    
      
    • 의도 분류: plan / fact / chat, 그리고 그 이유
    • 조건 추출: 날짜, 시작·끝 시각, 지역, 장르. 없는 값은 null
    • 쓸 Tool 후보 고르기 (Tool 설명의 "언제 부르는지"를 읽고)
    • judge 결과를 사람이 읽을 문장으로 만들기
    
    
    코드 맡는 일
    
      
    • 되묻기 판정 (끝 시각만 있고 시작 시각이 없을 때)
    • Tool 실행 순서와 인자 채우기, 결과 cache
    • 실패 신호를 공통 실패 코드로 바꾸기
    • 시간 계산, 맞음/안 맞음/제외 판단
    • 재계획 여부와 전략, 상한 3회
    • 계획 저장과 겹침 검사 (Tool로 만들지 않음)
    • M10 LLM 출력 바로잡기: 끝 시각이 시작보다 이른 오전이면 오후로 (_fix_afternoon)
    • M10 답변에 꼭 넣을 문장(집계 기준일, 재계획 경로)과 조건 조정 질문 여부 정하기, 남은 영어 키 이름 지우기
    
  
    

    



    
  
    
    F3001~F3004 · M2
    
    Tool 4종
    
    
    Agent(LLM)에게는 이름, 설명, 입력 스키마만 넘깁니다. 모든 Tool은 예외를 밖으로 던지지 않고 {"ok": true, "data"} 또는 {"ok": false, "error": {code, message}}를 돌려줍니다. 보라색 줄은 LLM이 읽는 설명입니다.
    
  
    
  
    
  
    
    
    실패 코드와 재계획
    
    
    
      
    코드뜻재계획?
    
      
        
    BAD_ARGUMENT입력이 규격과 다름 (날짜 형식 등)아니요
    
        
    INVALID_KEY키가 없거나 틀림아니요 · 다시 해도 같음
    
        
    UPSTREAM_ERROR시간 초과, 서버 오류아니요
    
        
    NOT_FOUND없는 식별자아니요 · 그 항목만 제외
    
        
    NO_DATA조회는 됐지만 결과가 비어 있음상황에 따라
    
        
    NO_RUNTIME러닝타임이 비어 있음아니요 · 그 영화만 판단 제외
